# XRR Fitter “Diffraction Workspace” GUI 设计规格

**日期：** 2026-08-23

**状态：** 已确认设计，等待高保真预览复核

**范围：** PySide6 桌面 GUI 的信息架构、交互与视觉系统

**不在范围：** 物理计算、拟合算法、公共 API、项目文件语义和导出语义变更

## 1. 目标与产品定位

XRR Fitter 同时服务两类同等重要的用户：

1. 实验室/工艺人员，需要批量导入、自动分组、拟合队列、异常处理、均匀性统计和可靠导出；
2. 薄膜研发人员，需要结构建模、参数与约束、候选比较、残差、SLD、相关性和不确定度分析。

新 GUI 不沿用既有界面的布局、面板体系或视觉形式。它只继承稳定的产品能力和科学语义，
用一个“双视角实验工作台”重新组织这些能力。

成功标准：

- 日常用户在三个主要决策内完成“导入 → 处理异常 → 运行”；
- 研发用户始终可见当前数据集、结构版本、拟合运行和候选身份；
- 批次操作和深度分析共享选择与状态，但不会在同一画面竞争注意力；
- 修改科学对象前明确说明结果失效范围；
- 运行、取消、恢复和错误状态持续可见且可恢复；
- 在 1280×760 到高 DPI 桌面环境中保持核心任务可用。

## 2. 设计原则

1. **按科学对象组织，而非按控件面板组织。**
2. **异常优先。** 正常项降低视觉权重，需人工介入的事项携带原因、影响和恢复操作。
3. **一个画面一个主操作。** 次要操作不得与当前任务竞争。
4. **渐进披露。** 参数、约束和详情只在选中对象时通过上下文工作表出现。
5. **版本身份显式。** 数据集、结构、运行、候选和发布快照不得被模糊替代。
6. **运行不阻塞。** 长时任务使用永久活动栏，不使用阻塞式进度弹窗。
7. **证据先于结论。** Confidence 必须连同降级原因和诊断证据呈现。
8. **颜色不是唯一编码。** 状态和曲线同时使用文字、形状、线型或标记。
9. **桌面原生。** 遵循键盘、焦点、高 DPI 和窗口尺寸约束，不机械套用移动端导航。

## 3. 对象模型与身份链

```text
项目
 └─ 导入批次
     └─ 数据集
         ├─ 结构版本
         ├─ 拟合运行
         │   └─ 候选解
         │       └─ 诊断证据
         └─ 发布快照
```

分析上下文必须展示完整身份，例如：

```text
S300 批次 / W02 / 结构 v4 / Run 08 / Candidate 02
```

结构修改创建新结构版本；旧运行和候选可以保留为历史证据，但必须明确标记为不再对应当前结构。
发布快照是复核后的不可变导出身份，而不是当前可编辑工作区的别名。

## 4. 顶层信息架构

项目内只有三个固定工作区：

### 4.1 批次

- 导入与自动分组；
- 数据源完整性；
- 单点/联合路由；
- 拟合队列、异常与恢复；
- 多点均匀性和状态总览。

### 4.2 分析

- 膜层结构与结构版本；
- 参数、边界、先验、约束与共享关系；
- 反射率、残差和 SLD；
- 候选解、Confidence、相关性和不确定度。

### 4.3 报告

- 数据源、模型、算法和候选身份复核；
- Confidence 降级原因；
- 可用诊断证据清单；
- 导出内容选择；
- 创建不可变发布快照。

不定义“新手模式”和“专家模式”。两类用户通过工作区进入自己的主要任务，同一科学对象在工作区
间保持选择和版本身份。

## 5. 应用框架

```text
┌──────────────────────────────────────────────────────────────┐
│ 项目身份与保存状态       批次｜分析｜报告       全局操作/运行 │
├──────────────────────────────────────────────────────────────┤
│ 数据集 / 结构版本 / 运行 / 候选上下文                        │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                    当前工作区主画布                          │
│                                                              │
│        选中对象时从右侧打开上下文工作表                      │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ Worker 状态 · 当前阶段 · 检查点 · 取消/恢复 · 运行日志       │
└──────────────────────────────────────────────────────────────┘
```

- 顶部项目栏固定，展示项目身份、保存/完整性状态、三个工作区和当前唯一主操作；
- 上下文条固定，展示当前数据集、版本、运行和候选；
- 主画布不保留永久左右三栏；
- 右侧上下文工作表按需打开，宽度在 360–400 px 间适配；
- 底部活动栏永久存在，但无运行时保持低视觉权重。

## 6. 批次工作区

### 6.1 导入工作表

导入分为“选择文件 → 检查自动识别 → 确认导入”。确认页按物理分组展示：

- 样品与点位；
- 推导出的膜层和基底；
- 仪器/光路预设；
- 自动生成的单点或联合拟合组；
- 解析失败项及其恢复操作。

有效项和失败项可以同时提交；失败项不得阻止同批其他有效数据。

### 6.2 异常队列

数据集矩阵上方只展示需要人工介入的事项，例如确认基底、重新链接源文件或补充材料 SLD。
每项包含原因、影响范围和一个明确恢复操作。解决后立即从队列移除。

### 6.3 数据集矩阵

每行代表一个数据集，核心列为：

- 源文件完整性；
- 自动结构识别；
- 单点/联合路由；
- 当前运行阶段；
- Confidence；
- 关键膜厚；
- 统计成员资格。

结果按“失败 → 需复核 → 多解/强相关 → 可信”排序。矩阵只将符合资格的数据集纳入统计，
并展示被排除项的原因。

### 6.4 主操作

按钮文本反映实际动作，例如“运行 12 个就绪数据集”“继续上次拟合”或“重新运行 3 个失效结果”。
运行进度出现在行内和底部活动栏，不覆盖矩阵。

## 7. 分析工作区

分析工作区包含三个任务透镜，不用大量图表标签页替代任务语义。

### 7.1 模型透镜

- 横向膜层轨道是结构的主要导航；
- 中央同步显示结构示意和 SLD；
- 选择膜层后打开参数工作表；
- 周期层、梯度层和基底保持真实层级；
- 应用修改创建新结构版本；
- 提交前显示哪些运行和候选会失效。

### 7.2 拟合透镜

- 主图展示实测数据、当前候选、对比候选、拟合区间和屏蔽点；
- 残差轨道与主图共享横轴；
- 运行配置从上下文工作表打开；
- 拟合期间曲线明确标为“实时预览/未发布”；
- 已发布候选和实时预览不可使用相同视觉编码。

### 7.3 证据透镜

按判断顺序展示：

1. Confidence 与降级原因；
2. 候选解之间的物理差异；
3. Profile likelihood；
4. 参数相关矩阵；
5. Bootstrap/MCMC 不确定度；
6. 边界命中和残差结构。

切换候选时所有证据同步更新。

## 8. 上下文工作表

工作表适用于数据源详情、膜层参数、边界与先验、共享规则、运行配置和候选详情。

- 宽度：1600×900 下约 400 px；较小窗口约 360 px；
- 不覆盖当前任务的关键主图；
- 标题区显示对象身份和关闭按钮；
- 修改使用“应用/放弃”，不在每次输入时改写项目；
- 字段错误显示在字段下方，并提供修复说明；
- 应用失败时保留输入；
- 应用科学对象变更前显示失效范围；
- `Esc` 关闭工作表，不用作拟合取消快捷键。

## 9. 运行、取消与恢复

底部活动栏展示：

- 数据集或联合组；
- 当前 stage 和完成度；
- best objective；
- 已用时间和预计剩余；
- 最新检查点；
- 协作取消、恢复和运行日志入口。

取消只请求协作取消，并说明检查点是否可恢复。强制停止是二级危险操作。Worker 错误必须说明：

1. 发生了什么；
2. 影响哪些数据集；
3. 哪些旧结果仍有效；
4. 用户下一步可以做什么。

## 10. 关键状态

### 空项目

展示支持的输入、命名方式、示例项目和唯一主操作“导入测量”，不展示空表格或空坐标轴。

### 已导入但需处理

显示待处理数量、原因、影响和恢复操作；有效数据仍可继续。

### 就绪

显示可运行数量、自动分组和被排除项，主操作为“运行 N 个数据集”。

### 运行中

底部活动栏持续更新，主窗口可继续读取已完成数据，实时曲线标记为预览。

### 已完成

优先显示 Confidence、降级原因和候选身份，区分“计算完成”与“结果可信”。

### 结果已失效

旧结果原位显示其结构版本和当前结构版本，提供“查看差异”和“重新拟合”。旧证据不静默删除，
也不继续伪装成当前结果。

## 11. 视觉系统

视觉概念名为 **Diffraction Workspace**：严格、可复核、克制的科学工作环境。

### 11.1 浅色令牌

| 角色 | 色值 | 用途 |
|---|---|---|
| Mineral | `#F4F3F0` | 主背景 |
| Paper | `#FCFBF8` | 工作表与图表表面 |
| Graphite | `#172026` | 主文字与坐标轴 |
| Slate | `#58646D` | 次级文字 |
| Diffraction Violet | `#5B4CC4` | 主操作、选择、当前对象 |
| Signal Teal | `#00777D` | 数据完整性、辅助曲线 |
| Success | `#24724E` | 可信、完成 |
| Warning | `#9A5A00` | 相关、多解、需复核 |
| Error | `#B4232A` | 失败、失效 |
| Divider | `#D6D9D8` | 边界和分隔线 |

经 WCAG 对比度核验：Graphite/Mineral 14.89:1、Slate/Mineral 5.47:1、Violet/Mineral
5.78:1、白字/Violet 6.41:1、Teal/Mineral 4.81:1。

### 11.2 深色令牌

- 背景 `#11161C`；
- 表面 `#181F27`；
- 主文字 `#E7EDF2`；
- 次级文字 `#A8B4BE`；
- 主色 `#A89BFF`；
- 辅助色 `#4AC7C8`。

深色主题单独校验，不由浅色简单反转。

### 11.3 排版和几何

- 中文：Noto Sans SC / PingFang SC / Microsoft YaHei；
- 拉丁文字：Inter；
- 数值、单位、哈希和目标函数：平台等宽字体；
- 字号：22 / 17 / 14 / 13 / 12 px；
- 4/8 px 间距体系，12 列工作网格；
- 页面边距 20–24 px；
- 输入和按钮高 36 px，表格行高 40 px；
- 普通圆角 6 px，工作表 10 px；
- 阴影仅用于工作表、菜单和模态窗口。

不使用科幻字体、玻璃拟态、Emoji 结构图标、装饰性渐变或大面积悬浮卡片。

## 12. 图表编码

| 数据对象 | 视觉编码 |
|---|---|
| 实测数据 | Graphite 圆点 |
| 当前候选 | Violet 实线 |
| 对比候选 | Teal 虚线 |
| 实时预览 | Amber 点划线并标注“未发布” |
| 被屏蔽点 | 空心叉号 |
| 不确定度 | Violet 低透明度带和边界线 |
| 异常点 | Error 菱形和文字标注 |

图表提供永久轴名称和单位、就地图例、十字光标、键盘替代操作、数据表视图，以及通过线型和
标记实现的色盲安全区分。二维数据不用 3D 图表表达。

## 13. 图标、动画与反馈

- 全局使用同一套约 1.75 px 线性矢量图标；
- 图标通常为 18 px，交互区域至少 36 px；
- 图标按钮有 tooltip 和可访问名称；
- Hover/Focus 120–150 ms；
- 工作表进入 180 ms；
- 工作区切换 200–220 ms 淡入；
- 不动画布局宽高，不做装饰性弹跳；
- reduced motion 下取消位移动画；
- 超过 300 ms 的工作必须显示状态反馈。

## 14. 键盘与无障碍

- Tab 顺序与视觉顺序一致；
- 焦点使用 2 px Violet 外圈；
- `Ctrl/Cmd+K` 打开命令搜索；
- `Ctrl/Cmd+Enter` 执行当前主操作；
- `Esc` 关闭工作表、菜单或对话框；
- 停止拟合使用独立命令；
- 图表提供键盘十字光标和数据表替代视图；
- 状态更新可被辅助技术宣告；
- 150% 缩放时关键按钮、错误和单位不截断；
- 正文对比度至少 4.5:1，图形和焦点指示至少 3:1。

## 15. 桌面适配

### 1600×900 及以上

- 完整批次矩阵；
- 400 px 工作表；
- 主图和残差同时显示；
- 膜层轨道显示完整名称和数值。

### 1280×760–1599×899

- 工作表缩至约 360 px；
- 次要矩阵列折叠到行详情；
- 膜层轨道缩短辅助说明；
- 不产生整个窗口的水平滚动。

在 125%、150% 和 200% 高 DPI 缩放下验证图标、字体、坐标轴、工作表关闭入口和主操作。

## 16. 实现边界与验收

### 实现边界

- GUI 继续只通过 `xrr_fitter.api` 使用领域能力；
- 不改变项目文件、计算、拟合、检查点和导出语义；
- 不新增兼容层、第二套状态机或静默 fallback；
- 不引入生产依赖，除非另行说明取舍并获得确认；
- GUI 重组必须以既有领域对象和显式 API mutation 为边界。

### 验收矩阵

- light/dark × 1280×760、1600×900、1920×1080 截图回归；
- 完整键盘遍历与焦点测试；
- 空、需处理、就绪、运行、取消、失败、失效和恢复状态测试；
- 长文件名、长材料名和中英文混排测试；
- 图表线型、标记、单位和数据表语义测试；
- 150% 和 200% 缩放检查；
- 现有公共 API 和科学计算行为回归；
- 1280×760 不裁切关键内容或产生全窗口水平滚动。

## 17. 非目标

- 不把桌面软件改成 Web 或移动应用；
- 不添加云账户、协作或远程计算能力；
- 不重新设计 XRR 算法和领域模型；
- 不以营销型 Dashboard、科幻 HUD、复古仪器或可任意拼装的 Dock 作为界面隐喻；
- 不为视觉效果牺牲数据密度、可访问性或可复核性。
